<Summary>

- **useEffect** চলে render-এর **পরে** — UI স্ক্রিনে আঁকা শেষ হলে বাইরের কাজগুলো এখানে হয়।
- **Dependency array** ঠিক করে কখন আবার চলবে: `[]` একবার, `[id]` id বদলালে, না দিলে প্রতিবার।
- Effect থেকে যে ফাংশন **return** হয়, সেটা **cleanup** — পরের effect-এর আগে আর unmount-এর সময় চলে।

</Summary>

<Concept>

React-এর মূল কাজ হলো state থেকে UI হিসাব করা — একই input দিলে একই output। কিন্তু একটা আসল অ্যাপের অনেক কাজ এই হিসাবের বাইরে পড়ে: সার্ভার থেকে data আনা, `document.title` বদলানো, WebSocket খোলা। এ ধরনের কাজকে বলে <Term id="side-effect">side effect</Term>।

Render-এর মাঝখানেই এসব করলে প্রতিবার render-এ নতুন request যাবে, আর React-এর হিসাবও এলোমেলো হয়ে যাবে। তাই নিয়মটা সহজ: আগে স্ক্রিনে আঁকো, তারপর effect চালাও।

<Steps>

1. **Render** — JSX হিসাব হয়
2. **Commit** — DOM-এ বসে, স্ক্রিনে দেখা যায়
3. **Effect** — fetch, timer, subscription
4. **Cleanup** — পরের effect বা unmount-এর আগে

</Steps>

### Dependency array-এর তিন রূপ

- `useEffect(fn)` — প্রতিটা render-এর পরে। বেশিরভাগ ক্ষেত্রে এটা দরকার হয় না।
- `useEffect(fn, [])` — শুধু প্রথম mount-এর পরে, একবার।
- `useEffect(fn, [a, b])` — a বা b বদলালে আবার চলে।

</Concept>

<Example>

একটা ইউজার প্রোফাইল component। `userId` বদলালে নতুন data আসবে, আর আগের অসমাপ্ত request বাতিল হবে।

```jsx title="UserProfile.jsx"
import { useEffect, useState } from "react"

function UserProfile({ userId }) {
  const [user, setUser] = useState(null)

  useEffect(() => {
    const controller = new AbortController()

    fetch(`/api/users/${userId}`, { signal: controller.signal })
      .then((res) => res.json())
      .then(setUser)
      .catch(() => {})

    // cleanup: userId বদলালে আগের request বাতিল হবে
    return () => controller.abort()
  }, [userId]) // userId বদলালেই effect আবার চলবে

  if (!user) return <p>লোড হচ্ছে…</p>
  return <h2>{user.name}</h2>
}
```

</Example>

<Mistakes>

নতুনরা useEffect নিয়ে সবচেয়ে বেশি যে তিনটা জায়গায় আটকায়।

1. **খালি array, অথচ ভেতরে userId** — অনেকেই প্রথমে dependency array খালি রেখে দেয়। তখন effect একবারই চলে — prop বদলালেও পুরনো data দেখায়। সহজ নিয়ম: effect-এর ভেতরে যা পড়া হয়, সব dependency-তে যাবে। ESLint-এর `exhaustive-deps` নিয়মটা চালু রাখলে এটা নিজেই ধরা পড়ে।
2. **Effect-এ setState, dependency-তে সেই state** — State বদলায় → effect চলে → আবার state বদলায়। ফলাফল infinite loop, ট্যাব জমে যায়। প্রায়ই দেখা যায় এটা আসলে effect-ই না — render-এর সময় সরাসরি হিসাব করে ফেললেই চলে।
3. **Cleanup ছাড়া fetch** — দ্রুত দুটো প্রোফাইলে ক্লিক করলে ধীর পুরনো response পরে এসে নতুনটাকে মুছে দিতে পারে — একে বলে <Term id="race-condition">race condition</Term>। `AbortController` দিয়ে cleanup-এ আগের request বাতিল করাই সমাধান।

</Mistakes>

### useEffect বনাম useLayoutEffect

useEffect চলে browser স্ক্রিন আঁকার **পরে**, তাই UI আটকায় না। useLayoutEffect চলে DOM বদলের পরে কিন্তু আঁকার **আগে** — কোনো element-এর মাপ নিয়ে সাথে সাথে position ঠিক করতে হলে (tooltip, popover) সেটা লাগে। অকারণে ব্যবহার করলে প্রতিটা frame দেরি হয়।

### Dependency তুলনা হয় `Object.is` দিয়ে

Render-এর ভেতরে বানানো object বা function প্রতিবার নতুন reference পায়, তাই effect প্রতিবারই চলে — দেখতে একই হলেও।

```jsx
// প্রতি render-এ নতুন object → effect প্রতিবার চলে
const options = { userId }
useEffect(() => {
  connect(options)
}, [options])

// সমাধান: primitive dependency
useEffect(() => {
  connect({ userId })
}, [userId])
```

### StrictMode-এ দুবার চলা

Development-এ React ইচ্ছা করে mount → cleanup → mount করে। এটা bug না — cleanup ঠিকমতো লেখা আছে কিনা যাচাইয়ের পরীক্ষা। Production build-এ একবারই চলে।

### Performance: সব কাজ effect না

Effect-এর ভেতরে setState মানে অন্তত একটা বাড়তি render। অন্য state থেকে হিসাব করা যায় এমন মান render-এর সময়ই বের করো, দরকার হলে `useMemo`। বড় অ্যাপে data fetching-এর জন্য framework বা React Query-র মতো library caching আর race condition দুটোই সামলায়।

<Practice>

- **বাগ খোঁজা:** আমাকে useEffect ব্যবহার করা ৫টা ছোট React component দাও, প্রতিটায় একটা করে লুকানো bug থাকবে। আমি নিজে খুঁজে বের করার পরে তবেই উত্তর দেখাবে।
- **ধাপে ধাপে বানানো:** একটা search box বানাতে চাই যেখানে debounce আর cleanup দুটোই লাগবে। সরাসরি সমাধান দিও না — প্রতিটা ধাপে একটা করে hint দাও।
- **কোড রিভিউ:** আমার এই component-টা review করো: কোন dependency বাদ পড়েছে, কোথায় race condition হতে পারে, আর কোন effect আসলে দরকারই নেই — কারণসহ বলো।

</Practice>
